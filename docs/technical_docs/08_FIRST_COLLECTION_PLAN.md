# 第一版数据采集计划表

这份计划表是给你当前项目第一阶段直接使用的，目标不是一次把所有动作评估做满，而是先稳定做出：

- 可复现的数据采集流程
- 第一版动作识别模型
- 第一版标准 / 错误动作区分

适用前提：

- 当前硬件为 `1 个 IMU + 1 个弯曲传感器`
- 当前 BLE 与电脑网关已经打通
- 当前网关可以保存 CSV，并支持后续在线识别

## 1. 第一版目标

第一版先完成这三件事：

1. 识别 `idle / squat / bench`
2. 在此基础上区分 `standard / wrong`
3. 证明实时识别链路能跑通

第一版先不要追求：

- 很细的代偿行为分类
- 很复杂的评分体系
- 多部位同步识别

## 2. 传感器佩戴方案

由于你当前是单 IMU + 单弯曲传感器，建议第一版按“单关节护具”思路来做。

### 深蹲采集

- 护具位置：膝关节
- 弯曲传感器：跨过膝关节弯折方向固定
- IMU：固定在膝盖外侧护具上，与弯曲片一起固定

### 卧推采集

- 护具位置：肘关节
- 弯曲传感器：跨过肘关节弯折方向固定
- IMU：固定在肘外侧护具上

说明：

- 第一版建议“深蹲”和“卧推”分开采，不要同一次佩戴位置同时兼顾两个动作。
- 也就是说：采深蹲时把设备当作“智能护膝”，采卧推时把设备当作“智能护肘”。
- 这样更符合你现在传感器数量少的实际情况。

## 3. 标签定义

第一版固定 5 个标签：

- `idle`
- `squat_standard`
- `squat_wrong`
- `bench_standard`
- `bench_wrong`

## 4. 错误动作定义

第一版每个动作只保留一种错误模式，避免标签混乱。

### 深蹲错误动作

标签：`squat_wrong`

定义：

- 下蹲和起身过程中，膝关节轨迹不稳定
- 可重点模拟“膝内扣明显”或者“蹲幅不足”

建议第一版只选一种：

- 推荐：`膝内扣明显`

原因：

- 对膝部护具上的 IMU 和弯曲传感器更容易形成差异

### 卧推错误动作

标签：`bench_wrong`

定义：

- 推起过程中肘部轨迹控制差
- 可重点模拟“肘外展过大”或者“动作幅度不一致”

建议第一版只选一种：

- 推荐：`肘外展过大`

原因：

- 对肘部弯曲和角速度信号更容易形成区分

## 5. 每类数据采多少

第一版建议总量：

- 每个标签 `12` 个文件
- 共 `5` 个标签
- 总文件数 `60`

这是一个比较稳的起点，既不会太少，也不会一上来采到人崩溃。

## 6. 每个文件怎么录

统一规则：

- 每个文件时长：`25` 秒左右
- 开始前静止：`2` 秒
- 动作持续：`20` 秒
- 结束后静止：`3` 秒

### idle

- 内容：自然站立或自然静止
- 时长：`25` 秒
- 文件数：`12`

### squat_standard

- 内容：标准深蹲
- 节奏：`2 秒下蹲 + 2 秒起身`
- 单文件次数：`5` 次左右
- 文件数：`12`

### squat_wrong

- 内容：固定一种错误深蹲
- 节奏：和标准深蹲尽量保持一致
- 单文件次数：`5` 次左右
- 文件数：`12`

### bench_standard

- 内容：标准卧推动作
- 节奏：`2 秒下放 + 2 秒推起`
- 单文件次数：`5` 次左右
- 文件数：`12`

### bench_wrong

- 内容：固定一种错误卧推动作
- 节奏：和标准卧推尽量保持一致
- 单文件次数：`5` 次左右
- 文件数：`12`

## 7. 第一版采集总表

| 标签 | 文件数 | 单文件时长 | 单文件动作次数 | 说明 |
|---|---:|---:|---:|---|
| `idle` | 12 | 25 秒 | 0 | 静止状态 |
| `squat_standard` | 12 | 25 秒 | 5 次左右 | 标准深蹲 |
| `squat_wrong` | 12 | 25 秒 | 5 次左右 | 固定一种错误深蹲 |
| `bench_standard` | 12 | 25 秒 | 5 次左右 | 标准卧推 |
| `bench_wrong` | 12 | 25 秒 | 5 次左右 | 固定一种错误卧推 |

总计：

- `60` 个文件
- 总采集时长约 `25 分钟`
- 加上穿戴调整和休息，建议按 `1.5 ~ 2 小时` 预算

## 8. 每天怎么分配最合理

建议拆成 3 天完成，不要一天全采完。

### 第 1 天：深蹲

- `idle`：4 个文件
- `squat_standard`：12 个文件
- `squat_wrong`：12 个文件

### 第 2 天：卧推

- `idle`：4 个文件
- `bench_standard`：12 个文件
- `bench_wrong`：12 个文件

### 第 3 天：补采与校正

- `idle`：4 个文件
- 补采信号差、掉包或动作不稳定的文件
- 每类补 `2~4` 个文件

## 9. 每次录制时必须保持一致的事

这些比“再多采 10 个文件”更重要。

- 同一个标签内，动作节奏尽量一致
- 同一个标签内，错误模式要固定，不要一会儿膝内扣、一会儿蹲不下去
- 传感器安装方向固定
- 弯曲传感器弯折方向固定
- 绑带松紧尽量一致
- 每次上电后先静止 `1~2` 秒再开始

## 10. 文件命名与备注建议

虽然网关会自动生成文件名，但备注建议这样写，便于回看：

### 深蹲标准

```text
膝护具_标准深蹲_第1组_节奏稳定
```

### 深蹲错误

```text
膝护具_错误深蹲_膝内扣_第1组
```

### 卧推标准

```text
肘护具_标准卧推_第1组
```

### 卧推错误

```text
肘护具_错误卧推_肘外展过大_第1组
```

## 11. 每个文件采完后的快速检查

每录完一个文件，快速确认：

1. 网关没有断连
2. 文件已经保存成功
3. `flexRawMv / flexIndex` 有明显动作变化
4. IMU 曲线不是一条平线

如果出现下面这些情况，这个文件建议直接废弃：

- 采集中断连
- 动作中途停顿太久
- 护具滑动明显
- 错误动作不稳定
- 文件里混入了多种动作模式

## 12. 第一版验收标准

采集结束后，第一版数据集至少要满足：

- 每个标签至少 `10` 个有效文件
- 每个文件长度基本一致
- 每个标签的动作模式清晰
- 深蹲和卧推信号有明显差异
- 标准和错误动作至少存在可观察差异

## 13. 采集完后立刻做什么

### 第一步：预处理

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\prepare-dataset.ps1
```

### 第二步：训练基线模型

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\train-baseline.ps1
```

### 第三步：回到网页重载模型

- 打开电脑网关网页
- 点击“重载模型”
- 开始实时识别测试

## 14. 第一版结束后再做什么

等第一版识别能跑通后，再进入第二版：

- 给 `squat_wrong` 增加第二种错误动作
- 给 `bench_wrong` 增加第二种错误动作
- 采不同受试者数据
- 做标准度评分
- 做长期训练报告

## 15. 我给你的最终建议

你现在不要贪多，第一版严格按这个顺序做：

1. 先采 `60` 个文件
2. 先训练第一版模型
3. 先验证实时识别
4. 再扩展错误动作种类

这样你这个课题会推进得非常稳，而且每一步都能形成成果。
