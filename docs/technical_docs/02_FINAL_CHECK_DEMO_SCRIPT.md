# 最终检查现场演示脚本

这份文档用于最终检查当天现场演示。目标不是讲得最长，而是按顺序把系统跑起来，让老师清楚看到：

1. 项目是完整闭环。
2. 设备能采集数据。
3. 网页和手机端有用户体验。
4. 模型可以识别动作。
5. 调试模式可以展示底层技术。
6. 数据库、报告、模型训练都有框架。

---

## 1. 演示前准备清单

### 1.1 硬件准备

| 项目 | 检查内容 |
|---|---|
| ESP32-S3 | 已烧录当前固件 |
| MPU6050 | 接线稳定，串口不再显示 `Connection failed` |
| 柔性传感器 | 弯曲时 ADC、电压、flexIndex 有变化 |
| 电源/USB | 供电稳定 |
| 绑带/泡棉 | 可以固定在腿部或手臂 |
| 手机 | 和电脑在同一网络 |

### 1.2 软件准备

| 项目 | 检查内容 |
|---|---|
| PC 网关 | 能启动到 `http://127.0.0.1:8787/login` |
| MySQL | 如果要展示用户系统，确保 MySQL 正常 |
| 浏览器 | 能打开网页 |
| 安卓 App | 能登录后端地址 |
| 模型文件 | `ml_pipeline/data/models/random_forest_model.joblib` 存在 |
| 训练数据 | 至少有 `idle` 和 `squat_standard`，最好有卧推动作数据 |

### 1.3 最好提前打开的页面

建议提前准备 3 个窗口：

| 窗口 | 地址 | 用途 |
|---|---|---|
| 网页登录页 | `http://127.0.0.1:8787/login` | 展示用户入口 |
| 网页调试页 | `http://127.0.0.1:8787/debug` | 展示模型和原始数据 |
| 手机 App | 后端地址 `http://电脑局域网IP:8787` | 展示移动端 |

## 2. 启动步骤

### 2.1 启动 PC 网关

在项目根目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\run-gateway.ps1
```

正常输出应该包含：

```text
本机访问地址：http://127.0.0.1:8787/login
手机访问地址：http://你的局域网IP:8787/login
```

如果 8787 被占用：

```text
端口 8787 已被占用，已自动切换到 8788
```

那浏览器和手机地址都要改成新端口。

### 2.2 打开网页

浏览器打开：

```text
http://127.0.0.1:8787/login
```

### 2.3 打开手机 App

手机端后端地址填写：

```text
http://电脑局域网IP:8787
```

不要写：

```text
https://...
127.0.0.1
localhost
```

## 3. 正式演示推荐顺序

## 第一步：介绍项目一句话

建议原话：

> 我的项目是一个基于柔性弯曲传感器和 IMU 的智能健身动作矫正系统。设备端用 ESP32-S3 采集弯曲和六轴运动数据，通过 BLE 传输到 PC 网关或手机端；PC 网关负责数据采集、模型识别、动作评分、用户系统和报告展示；网页和安卓端负责训练交互、实时反馈和历史报告。

老师如果点头，进入登录页演示。

---

## 第二步：展示登录/注册页

页面：

```text
/login
```

操作：

1. 打开登录页。
2. 指出支持注册、登录、游客浏览。
3. 如果已有账号，直接登录。
4. 如果想展示注册，创建一个简单账号。

建议说法：

> 这里是普通用户入口。用户只需要用户名和密码，注册成功后会直接进入个人首页。手机端和网页端共用同一个后端和数据库，所以账号可以互通。

如果老师问“游客能不能用”：

> 游客可以浏览页面结构，但不能真正保存个人训练记录。正式训练和报告需要登录账号。

## 第三步：展示用户个人首页

重点展示：

- 动作次数。
- 本周标准度。

如果老师问“热量怎么算”：

## 第四步：进入训练中心

页面：

```text
/training
```

操作：

1. 点击“开始训练”或导航到训练中心。
2. 展示左侧佩戴说明。
3. 展示设备连接区。
4. 展示右侧实时反馈区。

建议说法：

> 训练中心面向普通用户，用户不需要选择机器学习标签。用户只要连接设备并开始训练，系统会根据实时传感器数据自动识别动作，并显示动作、次数、标准度和纠正建议。

## 第五步：扫描并连接设备

页面：

```text
/training
```

操作：

1. 点击“扫描设备”。
2. 在下拉框中选择目标设备。
3. 点击“连接设备”。
4. 确认顶部状态变成已连接。

目标设备名：

```text
ESP32S3_Fitness_BLE
```

如果扫描到 Unknown：

建议说法：

> 有些 BLE 设备广播里没有 local name，可能显示 Unknown。后端会通过设备名、Service UUID 和 ESP32 字样综合判断候选设备。

如果连接失败：

现场补救：

1. 确认 ESP32 已上电。
2. 确认没有被手机 App 连接占用。
3. 断电重启 ESP32。
4. 刷新网页重新扫描。
5. 如果仍失败，切到调试模式展示已有数据和模型流程。

---

## 第六步：开始训练

操作：

1. 设备连接后，点击“开始训练”。
2. 先保持静止 1-2 秒。
3. 做几次深蹲或卧推动作。
4. 观察右侧实时反馈变化。

重点展示：

- 当前动作。
- 动作阶段。
- 动作次数。
- 标准度评分。
- 深度、稳定性、节奏。
- 实时纠正建议。
- 风险等级。

建议说法：

> 开始训练后，BLE 数据会通过 WebSocket 实时推送到网页。网页端根据模型识别结果和评估结果更新动作、次数、标准度和建议。

如果识别不准：

建议说法：

> 当前模型效果依赖采集数据质量和佩戴位置。如果静止被识别成动作，通常是静止样本不足或佩戴方式和训练数据不一致。解决方法是补采当前佩戴方式下的静止样本和动作样本，然后重新训练模型。

## 6. 常见现场异常和补救话术

### 6.1 网页打不开

检查：

1. PC 网关是否启动。
2. 端口是不是变成 8788。
3. 浏览器地址是否正确。

话术：

> 网关启动时会自动选择端口，如果 8787 被占用，会切换到 8788，所以需要看终端打印的实际访问地址。

### 6.2 手机 App 连接不上后端

检查：

1. 手机不能填 `127.0.0.1`。
2. 不能填 `https://`。
3. 手机和电脑必须同网。
4. 防火墙是否拦截。

话术：

> 手机端访问的是电脑局域网 IP，不是本机回环地址。`unable to parse tls packet header` 通常是把 HTTP 服务写成 HTTPS 访问。

### 6.3 BLE 扫描不到

检查：

1. ESP32 是否上电。
2. 是否已经被手机或电脑另一个程序连接。
3. 固件设备名是否一致。
4. 重启 ESP32。

话术：

> BLE 同一时间通常只能被一个客户端稳定连接，如果手机已经连接，网页端就可能连接失败。

### 6.4 MPU6050 连接失败

检查：

1. SDA/SCL 是否接对。
2. 供电是否正确。
3. I2C 地址是否被扫描到。

话术：

> 固件中即使 MPU6050 初始化失败，BLE 仍会启动，方便继续调试柔性传感器和通信链路。

### 6.5 静止识别成深蹲

原因：

1. idle 样本不足。
2. 当前佩戴方式和训练方式不同。
3. 标签不平衡。
4. 模型没有重载。

话术：

> 分类模型只能在训练过的类别里选择一个。如果静止样本不足或佩戴方式变化，它会把静止误判为最像的动作。解决方式是补采静止样本并重新训练。

### 6.6 模型训练失败

常见原因：

1. 少于两个有样本标签。
2. 每个标签 CSV 文件太少。
3. 窗口大小大于单个 CSV 数据长度。
4. CSV 缺少必要字段。

话术：

> 后端训练前会检查至少两个有样本标签。训练失败时调试模式会显示 prepare 和 train 的退出码以及日志，方便定位是数据预处理失败还是模型训练失败。

## 7. 检查当天最稳妥的展示重点

优先展示：

1. 网页 UI 已经像产品。
2. 登录注册和用户路径完整。
3. 设备连接和数据变化真实。
4. 调试模式能看到 flex 和 IMU 曲线。
5. 模型训练不是空口说，有训练入口、标签、样本数、模型状态。
6. 手机端和网页端账号逻辑互通。

不要主动强调：

- 当前模型准确率还不够高。
- 手机端语音兼容性问题。
- 深度学习还没做。
- 服务端复杂模型还没完全训练。

如果老师问，再如实解释：

> 当前是端到端原型，重点是打通硬件采集、实时识别、前端反馈和数据闭环。模型精度和复杂评估会随着后续数据量增加继续优化。
