# 中期检查功能框架说明

## 当前目标

本阶段优先完成“可展示、可演示、可继续扩展”的系统框架，而不是一次性把最终模型全部做完。

当前系统采用：

`ESP32-S3 采集端 -> BLE -> PC 边缘网关 -> 本地模型推理/启发式评估 -> 网页控制台`

后期再逐步补齐：

- 更多动作数据集
- 服务端复杂动作评估模型
- 设备端/移动端真实语音反馈
- 数据库和长期训练报告

## 课题 7 项内容映射

### 1. 设计集成柔性应变传感器和 IMU 的智能运动服/护具

当前状态：

- 已完成 IMU 与柔性应变传感器的基础集成
- 已完成膝部佩戴方案的初步验证
- 已形成左腿安装建议与硬件调试流程

后期补充：

- 更稳固的护具固定结构
- 更规范的佩戴工艺说明
- 多动作佩戴模板

### 2. 传感器数据通过蓝牙实时传输至手机或边缘网关

当前状态：

- ESP32-S3 已通过 BLE 实时发送 IMU + 弯曲传感器数据
- PC 网关已支持扫描、连接、断开、接收、录制
- 网页控制台可实时显示传感器数据

后期补充：

- 安卓端与网页端统一协议
- 数据断连重试与异常恢复优化

### 3. 在手机/网关上实现轻量级动作识别模型，识别深蹲、卧推等健身动作

当前状态：

- 已完成 `idle + squat_standard` 的轻量级二分类基线模型
- PC 网关已支持在线识别和模型热重载

后期补充：

- 增加 `squat_wrong / bench_standard / bench_wrong`
- 扩展为多动作、多类别识别

### 4. 服务端训练更复杂的动作评估模型，分析动作标准度、检测代偿行为

当前状态：

- 已搭建“动作评估框架”
- 网关侧已增加启发式标准度评分、动作阶段识别、代偿风险预警和纠正建议接口

说明：

- 当前是中期展示版框架，先用规则与实时信号实现可视化链路
- 后期可直接替换为服务端复杂模型输出

### 5. 设备端部署轻量化评估模型，实时提供语音纠正反馈

当前状态：

- 已搭建“语音反馈框架”
- 网页端改为显示文字纠正建议，不再提供用户侧语音开关
- 安卓端保留语音反馈入口
- 评估模块会生成可播报的纠正提示

后期补充：

- 优先完善安卓端或设备端真实 TTS
- 接入设备端轻量反馈模型
- 支持节流播报与场景化语音模板

### 6. 移动端显示实时动作数据、标准度评分和纠正建议

当前状态：

- PC 网关网页已经具备完整展示框架：
  - 实时传感器数据
  - 在线动作识别
  - 标准度评分
  - 纠正建议
  - 训练质量指标

后期补充：

- 将同类页面结构迁移到手机端
- 增加更贴近最终项目的移动交互

### 7. 生成个人训练报告，追踪长期进步趋势

当前状态：

- 已搭建“训练报告总览框架”
- 可展示：
  - 累计采集会话数
  - 标签覆盖率
  - 累计数据行数
  - 累计时长
  - 当前模型准确率
  - 近期采集趋势
  - 下一步里程碑建议

后期补充：

- 接入数据库
- 增加用户维度、动作维度、时间维度的长期分析
- 形成正式训练报告页面

## 当前中期可展示内容

1. 硬件端采集链路已经打通
2. BLE 边缘网关可以稳定接收与保存数据
3. 网页端可以显示 IMU 和弯曲传感器实时数据
4. 已有轻量级动作识别模型
5. 已有动作评分、纠正建议、语音反馈、训练报告的展示框架

## 当前框架的意义

这套框架的价值不在于“所有智能功能都已经最终完成”，而在于：

- 数据链路已经打通
- 识别闭环已经出现
- 评估与反馈接口已经预留
- 后期替换真实模型时不需要推翻现有系统结构

## 后期建议填充顺序

1. 补齐 `squat_wrong / bench_standard / bench_wrong`
2. 训练多类别动作识别模型
3. 用更复杂模型替换启发式评估
4. 接入真实语音反馈
5. 接入数据库与正式训练报告
