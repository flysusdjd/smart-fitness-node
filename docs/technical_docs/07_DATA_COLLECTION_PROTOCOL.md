# 智能健身项目数据采集规范

这份规范用于让 `ESP32-S3 + IMU + 弯曲传感器 + 电脑网关` 采出来的数据尽量稳定、可训练、可复现。

## 1. 采集前先固定的内容

- 传感器安装位置固定，不要今天绑一个位置、明天换一个位置。
- 每次采集都使用同一件护具或同样的绑带松紧度。
- ESP32 上电后，先保持自然姿态 `1~2` 秒，让基线稳定。
- 手机或电脑网关与设备距离保持在 `1~2` 米内，避免 BLE 丢包。

## 2. 第一阶段建议的标签

第一阶段先只做 5 类，不要一下子把错误动作拆太细：

- `idle`
- `squat_standard`
- `squat_wrong`
- `bench_standard`
- `bench_wrong`

建议：

- `squat_wrong` 第一版只保留一种主错误模式，例如“膝内扣明显”。
- `bench_wrong` 第一版只保留一种主错误模式，例如“肘外展过大”。
- 不要把多种错误动作混在同一个文件里。

## 3. 每个标签怎么采

建议第一批数据量：

- 每个标签录制 `10~15` 个文件
- 每个文件持续 `20~30` 秒
- 或者每个文件包含 `8~12` 次完整重复动作

推荐采集节奏：

- `idle`
  - 自然站立或静止坐姿
  - 每段 `20~30` 秒
- `squat_standard`
  - 节奏尽量稳定
  - 每段 `8~12` 次深蹲
- `squat_wrong`
  - 每段只保留同一种错误模式
  - 每段 `8~12` 次深蹲
- `bench_standard`
  - 每段 `8~12` 次卧推动作
- `bench_wrong`
  - 每段只保留同一种错误模式
  - 每段 `8~12` 次卧推动作

## 4. 每次采集时要记录的元信息

在网关界面里建议填写：

- `动作标签`
- `受试者编号`
- `备注`

备注建议写清楚：

- 传感器安装位置
- 当前动作是否标准
- 当前错误动作的类型
- 受试者是否疲劳

## 5. 采集过程中的注意事项

- 一个文件里只保留一种标签，不要中途切换动作。
- 开始采集后先静止 `2` 秒，再开始动作，结束前也静止 `2` 秒。
- 如果中途 BLE 明显掉包、网页卡死、设备断连，这段数据直接废弃。
- 如果传感器位置滑动了，这一整段数据不要继续用。

## 6. 第一批数据采完后的检查

每个标签至少检查 3 件事：

- `csv` 行数是否明显少于预期
- `flexRawMv` 和 `flexIndex` 是否随动作有节律变化
- `ax/ay/az/gx/gy/gz` 是否有明显动作波形

如果发现某个标签几乎没有波形差异，不要急着训练，先检查：

- 传感器安装位置是否合适
- 该动作是否真的能带动弯曲片变化
- 错误动作与标准动作是否区分足够明显

## 7. 训练流程

采集完成后，在项目根目录执行：

```powershell
.\ml_pipeline\.venv\Scripts\python.exe .\ml_pipeline\prepare_dataset.py
```

再执行：

```powershell
.\ml_pipeline\.venv\Scripts\python.exe .\ml_pipeline\train_baseline.py
```

训练完成后会得到：

- `ml_pipeline/data/models/random_forest_model.joblib`
- `ml_pipeline/data/models/metrics.json`

## 8. 在线识别怎么启用

训练好模型后：

1. 重新启动网关，或者
2. 在网页里点击“重载模型”

网关会自动读取：

- `ml_pipeline/data/models/random_forest_model.joblib`
- `ml_pipeline/data/processed/labels/label_map.json`

然后开始实时输出动作类别和置信度。

## 9. 第一版项目目标

第一版先追求下面这件事做成：

- 设备稳定采集
- 数据稳定保存
- 训练出能区分 `idle / squat / bench` 的模型
- 再逐步细化到 `standard / wrong`

这样推进最稳，也最符合你现在这个课题的节奏。
